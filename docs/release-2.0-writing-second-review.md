## Предлагаемый короткий контракт поведения

Это материал для отдельного Hub-эксперимента, не новая нормативная инструкция production. Он заменяет конфликтующие стилевые указания, а не добавляется поверх них. Действующие правила фактов, paid-media, языка, разделителей, Split и ручной отправки сохраняются.

> Respond to what this turn needs: answer a question, acknowledge something, ask a useful follow-up, make a relevant joke, or let the exchange end. Use as much text as the meaning needs. A reply can stand alone without a question or an emotional opener. Match the established persona's usual wording and rhythm; let slang, emoji and imperfect grammar come from that voice. Keep sympathy brief and specific when it fits. Ground factual claims, shared memories and current activities in supplied context. Examples demonstrate conversational choices, not facts about this conversation. When improving a draft, preserve its intent, conditions and commitments; return it unchanged if it already works.

Пять безопасных примеров для проверки разных функций хода; это не универсальный голос любой персоны:

| Полный необходимый контекст | Возможный ответ | Функция |
|---|---|---|
| Персона предпочитает кофе. «tea or coffee?» | “coffee, definitely” | Ответ без реакции и встречного вопроса. |
| «alright, talk tomorrow» | “night :)” | Завершение без удерживающего крючка. |
| «got promoted today» | “nice!! what’s the new role?” | Поздравление и содержательное уточнение без выдуманной истории о заслугах. |
| «missed my train by ten seconds» | “ten seconds is just rude” | Лёгкая реакция на конкретную деталь, без лекции. |
| Fix: «can we talk tomorrow instead?» | “can we talk tomorrow instead?” | Разрешено ничего не улучшать. |

Не копировать этот набор целиком в fast-reply: пример Fix принадлежит отдельному feature. Для fast-reply вместо него нужен context-complete пример спокойного сочувствия. Смысл набора — разнообразие функций, а не новое фиксированное соотношение вопросов и эмодзи.

## Few-shot, blacklist или второй редактор

| Подход | Решение для первого опыта | Основание и предел вывода |
|---|---|---|
| Короткий контракт + разные положительные примеры | Основной кандидат. Начать с 3–5 примеров в одном feature. | Anthropic рекомендует релевантные разнообразные примеры и положительные формулировки. Это обоснование метода, не измеренный выигрыш на нашей персоне. [Официальное руководство](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices). |
| Длинный blacklist | Не расширять. Использовать подозрительные слова/конструкции как диагностические признаки для ревью. | Запрет слова не задаёт альтернативное разговорное действие; это наш вывод из конфликтов шаблона. “actually” в исправлении факта может быть нормальным. Автоматическое удаление слова или середины сообщения способно потерять смысл. |
| Второй LLM-редактор | Отдельный поздний challenger, если первый кандидат не проходит человеческую оценку. | Self-Refine показал пользу итераций в изученных задачах, но не гарантирует улучшение casual-чата. Дополнительная последовательная генерация добавляет работу и ожидание; размер накладных расходов здесь не измерен. [Статья Self-Refine](https://arxiv.org/abs/2303.17651). |

Второй редактор не получает право «улучшать» цены, обещания или намерение. Он должен видеть исходный контекст и иметь вариант оставить текст без изменений. Итеративный self-refinement также может оптимизировать предпочтение оценщика в ущерб человеческой оценке: такой эффект показан для редактирования эссе, не для нашего продукта. Поэтому локальный judge не заменяет владельца. [Исследование reward hacking](https://arxiv.org/abs/2407.04549).

## Сопоставление с первым исследованием

Согласен с главным выводом, последовательностью «один feature → измерение → следующие шаблоны», запретом подменять качество лексическим фильтром и требованием проверять фактическую DB-персону. Независимо обнаружены те же reaction/question-примеры, неподтверждённый zip line и конфликт сохранения смысла в Fix. Совпадение исследователей усиливает приоритет проверки, но не доказывает эффект на реальных генерациях.

Уточнения:

- «Без валидации» нельзя превращать в «без сочувствия». Нужна проверяемая граница: пустая оценка человека и приписывание мотивов против уместного короткого участия.
- Двенадцать случаев из первого отчёта хороши как общий каталог, но для первого сравнения достаточно пяти fast-reply-ситуаций. Остальные features не следует смешивать в итоговый style score.
- Порог «две трети нетождественных побед» на маленькой выборке — эвристика, не статистическое доказательство. Показывать абсолютные win/tie/loss и сами дефекты; отдельно отмечать hard failures.
- Вопрос о разрешении вымышленных текущих действий не требуется для первого безопасного опыта: исходить из подтверждённых фактов. Менять это поведение можно обсуждать отдельно, не задерживая исследование естественного ритма.

## Один маленький следующий эксперимент

Подготовить пять синтетических fast-reply-входов: прямой вопрос, завершение, небольшая неприятность, хорошая новость и спорт без похудательного контекста. Добавить пять заранее написанных перефразировок как holdout. Зафиксировать одинаковые persona/model/settings, default mode и текущие фактовые/выходные ограничения.

После разрешения на генерации: baseline и кандидат, по два независимых ответа на каждый из десяти входов — 40 ответов, 20 пар. До запуска согласовать денежный предел. Порядок A/B скрыть и перемешать; сначала проверить факты и ответ на прямой вопрос, затем владельцу оценить «отправил бы / поправил бы / отклонил бы» и указать конкретный лишний фрагмент. Повторы opener/question считать только диагностикой.

Первый результат должен ответить на один вопрос: изменился ли выбор разговорного действия без потери смысла и голоса. Он не докажет рост конверсии, общее превосходство модели или качество остальных features. Здесь подготовлено предложение эксперимента; сам эксперимент не запускался.
