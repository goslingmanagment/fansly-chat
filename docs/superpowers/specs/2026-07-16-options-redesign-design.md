# Options-страница и changelog: редизайн (В3 «статус-первый»)

Дата: 2026-07-16. Статус: спека утверждается владельцем; мокапы —
артефакт «ChatGoose — редизайн настроек» (rev-3, вариант В3 выбран).

## 1. Контекст и цели

Текущая options-страница (main, 1.9.9) — один длинный скролл в семейных
токенах, но без семейных компонентов и структуры. Персоны уже read-only
каталог кернела (E36/E37, с 1.9.7+): карточки «key • version • status»,
preservation-note + export легаси-текстов, recovery-страница при битом
снапшоте. Подтверждённые боли: Hub-секция — стена статусных абзацев
(sign-in, legacy key, permission, connection вперемешку); сводного «всё ли
работает» нет вообще; копирайт английский при русскоязычной команде;
каталог персон показан сырыми ключами и версиями без человеческой подачи.

Цели редизайна, в порядке приоритета:

1. Одна страница обслуживает три роли: онбординг нового чаттера,
   ежедневную уверенность («всё зелёное — работаю»), диагностику владельца
   (за debug-режимом).
2. Структурное единообразие с десктопом: тот же каркас SettingsSurface
   (sticky-навигация + scrollspy + карточки-секции) и тот же словарь
   контролов (Button/Toggle/Chip/Badge, `.cap`/`.num`, автосейв-плашка).
3. Информативность из данных, которые кернел уже отдаёт: `/health`,
   `/auth/me`, квота из meta-фреймов, статус spenders-снапшота,
   persona-каталог.

Не-цели: переезд на фреймворк (остаёмся на plain TS + DOM), переключатель
языка (фиксированный RU с EN-терминами), тёмная тема для install/guide.

## 2. Зафиксированные решения владельца (16.07.2026)

1. **Персоны — только на беке.** Уже реализовано на main (E36 «Global
   personas are server-admin content», E37 follow-up): редактор и
   persona-sync удалены, секция читает каталог кернела, маппинг ведёт на
   ключи каталога, легаси-тексты preserved + export, есть recovery-режим.
   Редизайн модель НЕ меняет — только подачу каталога (см. §7) — и обязан
   сохранить preservation/recovery/export и future-schema barrier как есть.
2. **Выход — одна кнопка «Выйти»:** best-effort revoke device token на
   хабе + локальная очистка в любом случае, честный тост о результате.
   Отдельной «Забыть локально» нет.
3. **Язык — фиксированный русский** с EN-терминами (Hub, device token,
   Spenders, Reply/Fix/Ping — имена фич как в тулбаре).
4. **Тёмная тема веб-страниц:** changelog.html получает
   `prefers-color-scheme`-свап; install/guide сознательно светлые.
5. **Шрифты бандлим локально** (Source Serif 4 / Hanken Grotesk /
   IBM Plex Mono как файлы расширения) — страницы расширения (options,
   popup, debug-prompt) перестают ходить в Google Fonts CDN.

## 3. Информационная архитектура

Каркас — десктопный SettingsSurface: слева sticky-навигация (~150px) со
scrollspy, справа один скролл карточек-секций (максимум ~740px), заголовок
страницы «Настройки» серифом + версия-пилюля. Плавающая плашка
«Сохранено ✓» внизу справа (и красный твин при ошибке записи).

Порядок секций:

| # | Секция | Что в ней |
|---|--------|-----------|
| 0 | Герой готовности | чеклист-маршрут / пульс-строка (см. §4) |
| 1 | Статус | read-only ряды состояния (см. §5) |
| 2 | Agency Hub | адрес, вход устройства, доступ Firefox, legacy key, тест |
| 3 | Персоны | read-only каталог кернела |
| 4 | Аккаунты | Fansly-аккаунты: live-статус + маппинг персоны |
| 5 | Генерация | счётчики контекста; Advanced: debug |
| 6 | Вид | тема (chips System/Light/Dark) |
| 7 | Версия | версия, канал, кнопка Changelog |

«Account Mappings» и «Connection Status» текущей страницы сливаются в одну
секцию «Аккаунты»: это один список аккаунтов, показанный сегодня дважды.

## 4. Герой готовности

Одна карточка над секциями, два состояния:

**Маршрут** (пока есть незакрытые шаги) — заголовок «До работы — N шагов»
и три проверки по порядку, каждая со статусом и кнопкой-действием:

1. «Agency Hub подключён» — есть адрес + активный credential (device token
   предпочтительно) и последний тест соединения зелёный → иначе кнопка
   «Войти» (скролл к Hub-секции).
2. «Открой Fansly с аккаунтом модели» — известен хотя бы один аккаунт с
   живой сессией → иначе кнопка «Открыть fansly.com» (`tabs.create`).
3. «Назначь персону аккаунту» — у каждого аккаунта с живой сессией есть
   маппинг на активную персону каталога → иначе кнопка «К аккаунтам»
   (скролл).

**Пульс-строка** (все шаги закрыты) — карточка схлопывается в одну строку:
зелёная точка, «Всё работает», компактные mono-факты
(`Fansly 2 · Hub ✓ · AI 154 · Spenders 18 мин`), «развернуть ▾»
раскрывает полные ряды секции «Статус».

Проверки — те же источники, что и секция «Статус»; никаких новых запросов.
Ошибка любого шага формулируется действием («токен истёк → Войти заново»),
не диагнозом.

## 5. Секция «Статус»

Паттерн десктопного Activity: плоские ряды «точка + mono-бейдж + факт +
деталь справа», разделённые hairline. Только чтение.

Здоровье кернела и валидность credential'а — разные факты и разные ряды:
публичный `/health` про аутентификацию не говорит ничего, а 401 приносят
только аутентифицированные вызовы (`me` / тест соединения).

| Ряд | Бейдж | Источник | Честное пустое состояние |
|-----|-------|----------|--------------------------|
| Fansly | `CAPTURED N мин назад` / `OFF` | текущий `getSessionsSnapshot`. Семантика честная: «сессия захвачена», НЕ «живой пинг» — `connected` означает «креды получены и 401 с тех пор не было». Стор — память воркера: после его рестарта known-аккаунты без вкладки показываются по id | «аккаунты не обнаружены — открой Fansly» |
| Hub (core) | `UP` / `DEGRADED` / `DOWN` | `/health` (публичный): статус + db `latencyMs` (подписывать как задержку БД). Нюанс SDK: типизированный клиент бросает до парсинга 503-тела — DEGRADED читается через `raw('health')` + вендоренная схема или из `KernelApiError.body` | «адрес хаба не задан» |
| Доступ | `AUTH` / `401` / `НЕТ CREDENTIAL` | `me` (identity: username, роль, страницы) либо существующий тест соединения; при 401 кнопка «Войти заново» прямо в ряду | «войди или добавь ключ» |
| AI | `KERNEL` | quota-снапшоты из meta-фреймов ПО СТРАНИЦАМ (трекер уже пишет per-page — нужен новый runtime-read полной карты вместо popup-шортката «freshest across pages»): на каждую страницу «осталось N» (янтарный ≤20, красный 0 + время сброса). Метра «из N» нет (лимит кернел не сообщает); бюджет $ НЕ показываем — E14 прямо запрещает локальный рендер micro-USD (no-local-money-math) | «сегодня генераций не было — квота неизвестна» (правило попапа: не выдумывать числа) |
| Spenders | `RAMPED` / `FLAG OFF` / `NOT ALLOWLISTED` / `FAIL` | новый лёгкий status-трекер: наблюдение записывается при КАЖДОМ результате доски (включая ошибки/disabled/unsupported) с source-идентичностью и временем; options НИКОГДА не зовёт `getSpendersList` (это Fansly-запросы и нужна вкладка). Кэш доски таким источником не является: он ключуется на креатора/hub/лимит и стирается на disabled | «доска ещё не открывалась» |
| Контракт (только debug) | `MATCH` / `DRIFT` | `KERNEL_CONTRACT_HASH` вендоренного SDK против `health.contractHash` | — |

Ряды не блокируют рендер страницы (E35-дисциплина): каждый гидрируется
асинхронно, скелетон до ответа. Статусный цвет всегда продублирован
словом — не только точкой.

## 6. Секция «Agency Hub»

Ряды label-слева (как в десктопе, колонка ~150px):

- **Адрес хаба** — input; смена адреса, как и сегодня, сбрасывает статус
  теста и пересчитывает host-permission.
- **Вход устройства** — два состояния:
  - *не вошёл:* username + password + кнопка «Войти и выпустить token»
    (текущий `issueAgencyHubDeviceToken`-флоу; пароль не хранится);
  - *вошёл:* бейдж «активен», строка идентичности из `/auth/me`
    (`username · роль · страницы: …`), mono-строка токена
    (`agency_hub_device_XXXX… · продлевается при работе`). Префикс
    выводится из сохранённого токена; **точную дату истечения НЕ
    показываем**: метаданные выпуска не персистятся, `/me` их не
    возвращает, а sliding-expiry делает сохранённую дату выпуска враньём.
    Точная дата — только в transient-сообщении сразу после входа (как
    сегодня). Будущая core-операция current-token-info — за скоупом
    (кросс-репо).
  - Кнопка **«Выйти»** — протокол, а не «revoke и стереть»:
    1) отменить debounced/очередные снапшоты формы (стейл-сейв не должен
       реиграть креды после выхода);
    2) `DELETE /auth/device-tokens/current` с explicit device-token
       bearer (операция отвергает API key), таймаут ~5 с;
    3) в `finally` — локальная очистка: custody-поля пишутся ПУСТЫМИ
       строками, не удалением ключей (удаление открыло бы fallback на
       легаси-значение внутри settings-блоба);
    4) pagehide-путь после выхода не должен сериализовать старый ключ
       (dirty-флаги сброшены до записи);
    5) тосты различают исходы: «токен отозван на хабе» / «хаб ответил
       401 — токен уже был недействителен» / «хаб недоступен — токен
       стёрт локально, на сервере умрёт по sliding-expiry»; отдельный
       красный тост, если ЛОКАЛЬНАЯ запись не удалась (креды ещё на
       месте).
- **Доступ Firefox** — host-permission как бейдж («разрешён» /
  «не выдан» + кнопка «Разрешить»), вместо сегодняшних четырёх абзацев
  состояний. Тексты ошибок permission-API сохраняются в meta-строке.
- **Legacy chatter key** — свёрнутый `<details>` «на период миграции»
  с текущим полем + Show/Hide. Вся custody-логика (E19: отдельные ключи
  хранения, dirty-tracking, гонки сейвов) переносится без изменений.
- **Футер** — строка последнего теста («Проверено N мин назад — соединение
  OK» / код ошибки с расшифровкой) + кнопка «Проверить соединение».
  Семантика теста не меняется, меняется только подача (одна строка
  вместо четырёх статусных блоков).

## 7. Секция «Персоны» (read-only каталог — подача, не модель)

Модель уже отгружена (E36/E37, main): каталог кернела в persisted state
(`personaCatalog` + `personaCatalogSource`/`personaCatalogFetchedAt`),
маппинг строится из каталога с гейтом `findActivePersona`, кэш Fan Summary
уже ключуется на `personaDefinitionId`/`version`, легаси-тексты preserved,
есть export-контролы и recovery-страница при битом снапшоте. Редизайн
меняет только подачу:

- Ряд каталога вместо сырой строки «key • version N • status»: имя
  жирным, бейдж `built-in` для `builtin:lora` (клиентская проверка по
  `BUNDLED_LORA_PERSONALITY_ID`), mono `vN`, счётчик «аккаунтов: N» из
  локальных маппингов. Пер-персонного времени обновления НЕТ и не
  рисуем — каталог-схема несёт только key/displayName/version/
  definitionId/status. Архивные персоны приглушены и показываются только
  пока на них ссылается маппинг (подсказка «выбери замену»).
- Подвал секции: «каталог изменялся N мин назад» из
  `personaCatalogFetchedAt` — именно «изменялся»: метка не двигается при
  byte-identical рефреше, это last-changed, а не last-checked.
- Копирайт про редактирование — честный: «голоса управляются на сервере
  агентства; редактирование сейчас заморожено — включится владельческой
  консолью хаба». Сегодня авторить персоны НЕЛЬЗЯ нигде: дашборд-мутации
  выключены флагом и руты отвечают 409 (core #151, до закрытия
  legacy-LWW-лейна); писать «редактирует владелец в хабе» — враньё до
  этого core-релиза. Кросс-репо пререквизит фиксируется в плане.
- Offline-нюанс: кэш каталога привязан к точному источнику
  (`baseUrl|sha256(bearer)`) — это граница полномочий, а не оффлайн-кэш:
  ротация токена или смена адреса прячет каталог до первого успешного
  рефреша, и маппинги на это время выглядят «не в каталоге». UI в этом
  состоянии говорит «каталог для новых кредов ещё не загружен», а не
  «персона удалена».
- Preservation-note и export-контролы легаси-текстов остаются в секции,
  в новом визуале (ghost-кнопка + meta-строка).
- **Recovery-страница** (`renderLegacyPersonaRecovery`) остаётся
  полноэкранной заглушкой ВНЕ нового каркаса — она сознательно блокирует
  обычные настройки; получает новые токены/компоненты, но не навигацию.
- **Future-schema barrier (E37) переносится как есть**: наблюдатель
  `schemaVersion` ставится до первого чтения, pagehide не сериализует
  устаревшую форму. Новый каркас не должен добавить путей записи в обход
  барьера.

Не делаем: полнотекстовый `aiPersonasList` не используется (текст персоны
расширению не нужен); никакой storage-миграции для персон (не требуется);
редактор не возвращается. Чаттер не может завести голос сам — это действие
владельца (хаб/десктоп), UI говорит об этом прямо.

## 8. Секция «Аккаунты»

Одна строка на известный аккаунт: аватар-плейсхолдер (инициалы),
`displayName @handle`, статус точкой + честным словом («захвачена ·
N мин назад» / «нет сессии») — это факт захвата кред, не живой пинг.
Имя/хендл живут в памяти воркера: для known-аккаунта без открытой
вкладки после рестарта воркера строка честно деградирует до account id
(персистентные метаданные аккаунтов — за скоупом; при желании это
отдельный v15). Справа select персоны из каталога.
Без персоны — янтарный бейдж «AI отключён» (формула десктопа: unmapped =
gate). Пустое состояние: «аккаунты не обнаружены — открой Fansly», кнопка.
Сохранение маппинга — как сегодня (`saveAccountMapping`), select
блокируется на время записи.

## 9. Секции «Генерация», «Вид», «Версия»

- **Генерация:** четыре счётчика (Reply+Help, Ping, Fix, Deep) в гриде
  2×2, mono-инпуты, текущие клампы сохраняются. Блок `Advanced`
  (микро-cap): toggle «Debug mode» с подсказкой «окно отладки промпта +
  ряд Контракт в статусе».
- **Вид:** тема chips `Системная / Светлая / Тёмная` (замена select).
- **Версия:** mono `v X.Y.Z` из манифеста, «канал: self-hosted feed»,
  кнопка «Changelog» → `tabs.create` на
  `https://…/changelog.html#v<major>-<minor>-<patch>`, подсказка «Firefox
  обновляет сам; форсировать — about:addons».

## 10. Компоненты и исполнение

- Примитивы переносятся из десктопа 1:1 по визуальной спеке (значения —
  в отчёте по desktop-репе и мокапах): Button (primary/ghost/danger),
  pill-Toggle 18×32 с clay-заливкой, Chip с инверсией выбранного,
  Badge (neutral/green/amber/bad/clay + mono-вариант), `.cap` (10px,
  0.12em, uppercase), `.num` (mono + tabular-nums), карточка секции
  (radius 9px, `--chatgoose-shadow`, serif-заголовок 15px + hint 12px).
- Токены уже общие — `src/options/styles.css` расширяется классами
  компонентов; тёмная тема остаётся чистым свапом переменных.
- Plain TS + DOM, без фреймворка (конвенция репо). `src/options/index.ts`
  (1451 строка) при этом дробится: `sections/*.ts` по секции + общий
  каркас (nav/scrollspy/автосейв) — границы фиксируются в плане.
- Вся существующая дисциплина сейвов сохраняется: debounce + flush на
  blur/change/pagehide, custody-ключи, «первое чтение не мутирует»,
  неблокирующая гидрация аккаунтов, сериализация записей. При распиле
  на секции write-контроллер остаётся ОДИН, центральный: секции не
  читают и не пишут storage самостоятельно.
- Каждый асинхронный статус-запрос (health/me/каталог/квота) несёт
  generation/signature текущего подключения: медленный ответ от хаба A
  не должен раскрасить статус уже введённого хаба B (паттерн уже есть у
  connection-теста — распространяется на новые ряды).
- Автосейв-плашка: зелёная «Сохранено ✓» после успешной записи, красная
  с текстом ошибки при неуспехе; `prefers-reduced-motion` уважается.
- Шрифты — локальные woff2 в бандле расширения, `@font-face`; Google
  Fonts удаляется из ВСЕХ страниц расширения (options И popup — оба
  сейчас ходят в CDN; проверить debug-prompt). Это работа в
  `esbuild.config.mjs` (сейчас copy-таргет только для иконок) — новый
  assets-копир для шрифтов.

палитра `--paper/#f6f2ea … --clay/#c4704b`, гусь-маскот в шапке.

- Канон соответствия: `CHANGELOG.md` — полный архив (62 версии),
  страница исторически начата позже (54 карточки; восьми релизов 1.2.x
  на ней никогда не было) — НЕ бэкфилим, расхождение фиксируется как
  осознанное: страница = «что видели пользователи», markdown = полная
  история.
- Резюме релиза — серифом, самый громкий текст карточки; группы —
  cap-подписи с точкой: Исправлено (green), Изменено (neutral),
  Новое (clay); вехи — clay-рамка карточки. Синий из старой страницы
  уходит.
- Группы «Технически» сворачиваются в `<details>`; релизы старше трёх
  последних рендерятся свёрнутыми до резюме.
- Тёмная тема: `prefers-color-scheme` свап токенов.
- **Инвариант деплоя:** разметка обоих штамп-слотов сохраняется байт-в-байт

  Контент всех существующих релизов (30+, до текущего 1.9.9) переносится

## 12. Данные и отказы

Используемые операции кернела (наличие в вендоренном SDK проверено):
`health` (публичный; DEGRADED — через `raw('health')`/`KernelApiError.body`,
типизированный клиент бросает до 503-тела), `me`, `aiPersonaCatalog`,
`authRevokeCurrentDeviceToken`, существующие `issueAgencyHubDeviceToken` /
тест соединения. Квота — per-page карта локальных снапшотов meta-фреймов
(новый runtime-read; micro-USD по-прежнему не рендерим — E14). Spenders —
новый лёгкий status-трекер наблюдений (пишется при каждом результате
доски); options не инициирует Fansly-запросы. Новых обращений к Fansly
нет (DP 1-B не расширяется). Каждый источник отказывает независимо и
честно («неизвестно» вместо выдуманного значения); недоступный хаб не
блокирует локальные настройки. Квота- и spenders-наблюдения —
session-масштаб, схему хранилища не двигают.

## 13. Фазы

1. **Ф1 — каркас и словарь.** Навигация + scrollspy, карточки, примитивы,
   RU-копирайт, автосейв-плашка, слияние «Аккаунты», legacy key в
   свёртку, локальные шрифты. Без новых данных. Страница уже «как
   десктоп».
2. **Ф2 — информативность.** Секция «Статус» + герой готовности:
   health (UP/DEGRADED/DOWN) и Доступ (me/тест) раздельно, per-page
   quota-read, spenders status-трекер, контракт-ряд за debug, кнопка
   Changelog с якорем (деплой страницы — раньше этого релиза).
3. **Ф3 — витрина персон + выход.** Каталожная секция в новом визуале
   (перенос preservation/export, recovery-страница на новых токенах),
   кнопка «Выйти» по протоколу из §6. Storage-миграции нет.
4. **Параллельный трек — changelog.html** (независим от кода расширения):
   перенос в веб-регистр, даты, якоря, свёртки, тёмная тема,
   штамп-слоты.

Каждая фаза шипается отдельным релизом и полезна сама по себе. Порядок
жёсткий только в одном месте: обновлённый changelog.html с якорями
деплоится раньше (или вместе с) релизом Ф2, добавляющим кнопку с якорем —
ссылка не должна выйти раньше цели. Storage-миграций нет ни в одной фазе.

## 14. Приёмка (ключевые проверки)

- Онбординг с чистого профиля: герой ведёт за ≤3 действия до зелёного;
  каждый шаг кликабелен и попадает в нужную секцию.
- Хаб недоступен: страница открывается, локальные настройки работают,
  ряды статуса деградируют поодиночке с честными формулировками; «Выйти»
  стирает локально и говорит об этом. Здоровье кернела и валидность
  credential'а никогда не смешиваются в один индикатор.
- «Выйти» покрыт кейсами: успешный revoke / хаб вернул 401 / хаб
  недоступен / локальная запись не удалась — четыре разных исхода с
  разными сообщениями; после любого выхода pagehide не возвращает
  креды.
- Квота: без генераций сегодня — «неизвестно»; после генерации — число
  из meta-фрейма ДЛЯ КАЖДОЙ страницы отдельно; исчерпание —
  янтарный/красный с временем сброса; долларов на странице нет (E14).
- Аккаунты: после рестарта воркера у неоткрытого аккаунта строка
  деградирует до id без падения и без выдуманного имени; копирайт
  говорит «захвачена», не «жива».
- Персоны: preservation/recovery/export-механика E36/E37 сохраняется (их
  тесты остаются зелёными без ослабления); архивная персона в маппинге
  видна и требует замены.
- Deploy: `pnpm check` зелёный, стамп-слоты чейнжлога проходят
  `release-pages.test.ts`, `scripts/deploy.sh` штампует без правок.
- Тёмная тема обеих поверхностей — чистый свап токенов, без
  per-component стилей.
