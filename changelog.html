История обновлений ChatGoose

1.5.3 Текущая

Продолжение чистки бара из 1.5.2 — по фидбэку операторов. Редкие действия Scan и Multi уехали в выпадающее меню ⋯ у правого края (рядом с именем модели), а смена тона больше не стоит лишнего клика: меню тонов раскрывается по наведению на ▾.

Новое
  • Меню ⋯ для Scan и Multi. Кнопки Scan (профиль фаната) и Multi (разбивка на несколько сообщений) убраны из ряда в компактное меню ⋯ у имени модели — бар стал короче. На свёрнутой ⋯ остаются оба сигнала: зелёная точка = саммари готово, синий акцент = Multi включён
  • Тон по наведению. Меню тонов у Reply раскрывается, когда наводишь на ▾ — без отдельного клика «открыть». Навёл → один клик по тону = генерация. Раньше смена тона стоила двух кликов
Технически
  • Меню ⋯ зеркалит тон-меню (всплывает вверх, выровнено по правому краю — раскрывается влево, за край не вылезает); одновременно открыт только один поповер. S-хоткей Scan работает как прежде
  • Hover-open у каретки: задержка-намерение 110 мс (быстрый проезд к Polish/Hi не мигает меню) и grace 160 мс на закрытие (успеть зайти в поповер через зазор); клик по-прежнему переключает
  • 829 тестов проходят (4 skipped), typecheck и build чистые; добавлено покрытие меню ⋯ и hover-логики
1.5.2

Точечное улучшение к 1.5.1: бар действий стал компактнее и чище. Тоны ответа (Flirty/Upsell/Horny) переехали из отдельного ряда в выпадающее меню у кнопки Reply — как в десктопной версии, а чипы хоткеев на macOS ужались до буквы. Бар больше не упирается в край узкого диалога.

Новое
  • Тоны в меню у Reply. Каретка ▾ рядом с Reply открывает список тонов (Casual/Flirty/Upsell/Horny); клик по тону сразу генерит ответ в нём — один клик, одна генерация (как в десктопе). Отдельный ряд из трёх пилюль убран, бар стал заметно у́же
  • Компактные чипы хоткеев на macOS. На маке чип теперь показывает только букву (E/F/…), как на Windows/Linux — полное ⌘⇧E осталось в подсказке при наведении и шпаргалке ?. Раньше пять полных комбо распирали ряд
Технически
  • Reply — сплит-контрол (тело + каретка ▾), меню тона всплывает над баром; у тулбара убран скролл-обрез — ряд переносится, а не клипается
  • Клик по тону армирует тон и сразу запускает fast-reply (как в десктопе); ⌘⇧O по-прежнему листает тон. Меню закрывается по клику вне и Esc, каретка отключается во время операции
  • 824 теста (820 проходят, 4 skipped), typecheck и build чистые; тесты бара переписаны под меню
1.5.1

Точечное улучшение к 1.5.0: горячие клавиши теперь видно прямо в интерфейсе, а не только в шпаргалке по ?. На кнопках действий и в футере доски «Спендеры» появились чипы-клавиши с сочетанием, плюс подсказка при наведении.

Новое
  • Чипы хоткеев на кнопках. На кнопках Reply/Polish/Hi/Ping/Scan теперь видно сочетание: на macOS — полное ⌘⇧E, на Windows/Linux — буква (полное комбо в тултипе при наведении). Раньше шорткаты были «скрытыми» — узнать их можно было только через ?
  • Подсказки в доске «Спендеры». В футере доски — настоящие клавиши-чипы J/K/Enter/Esc вместо простого текста
Технически
  • Переиспользуемый кейкап .chatgoose-kbd + хелпер makeKbd() — единый визуал клавиши для бара кнопок, футера доски и шпаргалки ? (один источник, чтобы стиль не расходился)
  • Чипы внутри кнопок декоративные (aria-hidden), сочетание уходит ассистивным технологиям через aria-keyshortcuts — доступное имя кнопки остаётся чистым
  • 824 теста (820 проходят, 4 skipped), typecheck и build чистые; дифф проверен адверсариально (a11y, вёрстка чипов, порядок спиннера)
1.5.0

Первый релиз с новыми фичами после технической серии 1.4.x. Перенесли два удобных решения из десктопной версии ChatGoose: полноценные горячие клавиши для всех AI-действий прямо в диалоге и доску «Спендеры» — рейтинг фанов по сумме трат.

Новое
  • Горячие клавиши. Все AI-действия в открытом диалоге теперь на клавишах: Fast Reply, Polish, Help, Hi, Ping, Scan, Chat Review, переключение тона и отмена. По ? — шпаргалка со всеми сочетаниями
  • Кросс-платформенно. На macOS — ⌘⇧‹буква›, на Windows/Linux — Alt+Shift+‹буква›: Ctrl+Shift+‹буква› на Windows занят самим Firefox и не перехватывается из страницы, а Alt+Shift свободен и работает надёжно
  • «Спендеры» — доска топ-плательщиков. Рейтинг фанов по сумме всех трат, с разбивкой по тирам (🐳 Кит / ⭐ Топ / ✅ Прайм / Базовый / Низкий / Микро). Открытие кнопкой $ или хоткеем; навигация J/K, открытие чата по Enter/клику, фильтр по тирам, «Обновить»
Технически
  • Чистый движок сопоставления клавиш (shared/keymap.ts) + единая таблица биндингов (shared/hotkeys.ts) с платформо-зависимым модификатором; один центральный keydown-listener вместо разрозненных обработчиков
  • Доска собирается в фоне: messaging/groups + earnings/stats/accounts по каждому фану, затем ранжирование; скан ограничен (top-N недавних), низкая конкуренция и кэш 10 минут, чтобы не нагружать Fansly; тиры считаются на клиенте по порогам
  • Новый runtime-запрос getSpendersList; пороги тиров, сборка списка и движок клавиш — чистые функции с тестами
  • 822 теста (818 проходят, 4 skipped), typecheck и build чистые; дифф проверен адверсариально (корректность ранжирования и интеграция хоткеев)
1.4.1

Технический релиз вслед за 1.4.0 на пути к 2.0: код разнесён по модулям с явными границами, на входящих сообщениях добавлена валидация, подключён CI, а кэш Fan Summary стал аккуратнее. Новых фич и изменений в работе кнопок нет.

Главное

  • При удалении личности убираются все связанные с ней саммари, включая записи, что ссылаются на неё по personalityId (раньше оставались «осиротевшие»)
  • При переполнении квоты storage сначала освобождаются невалидные записи кэша, и только потом самые старые
  • Расширение устойчивее к неожиданным внутренним сообщениям: входящие runtime/port-сообщения проверяются по форме и отбрасываются, если не подходят
  • В README явно описано, какие данные уходят наружу: Agency Hub — строго opt-in, а usage-метрики не содержат текст переписки, промптов, ключей и Fansly-сессии
Технически
  • Новый shared/protocol.ts с type-guard'ами; runtime-api.ts и port-client.ts валидируют сообщения на границе доверия вместо as
  • Жизненный цикл операций вынесен в OperationRegistry, OperationTimeoutController, operation-cleanup, conversation-context-loader
  • Frontend разнесён по границам: surface-planner (inline vs overlay как чистая функция), ui/view-helpers; options/index.ts распилен на agency-hub-settings, dom, sessions
  • Граница storage подчищена: storage-coordinator, migrations, summary-cache (новые хелперы чистки/эвикции кэша)
  • Добавлен CI (.github/workflows/ci.yml) и скрипт npm run check (typecheck + test + build)
  • Юнит-тесты на новые модули; 783 теста всего (779 проходят, 4 skipped), typecheck и build чистые
1.4.0

Большой проход по code review всей кодовой базы, подготовка к 2.0 релизу: устранены утечки, гонки и слабые места в надёжности в background, content и UI. Новых фич нет — только стабильность и корректность.

Главное
  • Rate limit от Fansly (429) обрабатывается корректно: читается Retry-After и показывается понятная ошибка про лимит со временем повтора
  • Переход между диалогами во время Scan / Summary / Review / Help больше не оставляет зависший overlay и не кэширует результат прошлого фана в новом диалоге
  • Клик по фиче в момент переподключения к фону больше не оставляет кнопку в вечной загрузке
  • Кнопки и overlay восстанавливаются, даже если Fansly пересобрал DOM диалога с задержкой
  • Редактирование личности больше не сбрасывает фокус и курсор; удаление не воскрешает личность из-за отложенного сохранения
  • Поле количества сообщений показывает реально сохранённое (обрезанное) значение
  • Одноимённые личности различаются в списке привязок по короткому id
  • Попап не открывается пустым, если фон временно недоступен
  • Реплики со словом «instructions» (например JOI) больше не вырезаются фильтром meta-leak
  • Активная подписка с прошедшей датой окончания не показывается как «заканчивается через N дней»
Технически
  • Устранены неограниченные утечки Set отменённых operation id (feature и compare)
  • LLM-стримы освобождают reader и HTTP-тело на всех путях выхода, включая throw из середины цикла
  • SSE-парсинг устойчив к CRLF; reasoning-колбэки OpenRouter не срабатывают для отклоняемых chunk-ов
  • Классификация ошибок провайдеров не матчит широкие подстроки billing / not found
  • Конкурентные старты операций сериализуются синхронным резервированием вкладки (TOCTOU)
  • Fansly-клиент: итеративные ретраи, Retry-After → rate_limited, кап пагинации, общая retry-политика
  • Сессии обновляют креды и disconnect in-place, чтобы in-flight пагинация подхватывала релогин
  • Миграция storage гардит personalities / accountMappings; hi-greeting восстановил prompt caching
  • Добавлено 22 regression-теста (745 всего); typecheck и build чистые

1.2.17

Финальная v2-проверка PPV в ChatGoose. Главный баг прошлой версии был в том, что расширение смотрело на «куплено» с точки зрения модели / viewer-side флагов Fansly. Для модели свой PPV-контент часто выглядит доступным, поэтому AI мог решить, что фан уже купил видео или бандл, и отвечать так, будто контент разблокирован.

Теперь ChatGoose проверяет покупку с точки зрения конкретного фана. Это снижает риск неправильных PPV-ответов и ложных предположений о покупке, но не обещает идеальное совпадение со всеми внутренними состояниями Fansly: если доказательств не хватает, статус остаётся unknown.

Главное
  • purchased ставится только когда найден точный заказ этого фана на этот конкретный PPV-контент
  • not purchased ставится только после успешной точной проверки /media/orderhistory, если заказ для пары «фан + контент» не найден
  • unknown ставится, когда не удалось определить фана, нет нужных API-данных, проверка заказа не сработала, упала, истекла по таймауту или часть вложений не попала в лимит проверок
  • Чаевые и embed-only сообщения (GIF/превью ссылок) больше не превращаются в ложные [Media]
Подробности
  • Проверка идёт с fan-perspective: media.purchased и похожие model-side/viewer-side флаги больше не считаются доказательством покупки фаном
  • Для неподтверждённых PPV-вложений ChatGoose делает exact /media/orderhistory check по accountMediaId или accountMediaBundleId и accountIds=<fanAccountId>
  • Метки медиа и бандлов стали точнее: nested mimetype fallback, состав через bundleContent[] / accountMediaIds[], правильные формы 1 Photo, 2 Videos
  • Пример новой метки: [Media Bundle: 1 Photo, 2 Videos — PPV $20.00, unknown]
  • Промпты fast-reply, improve-draft, help-me и ping теперь прямо говорят AI не цитировать PPV-цены/теги фану и не утверждать «купил» или «не купил» при unknown
Технически
  • normalizeTranscript() принимает PurchaseEvidenceOverride: inline /message.accountMediaOrders[] даёт только positive proof, а checkedNotPurchased* приходит только из exact verifier
  • Inline single засчитывается только как accountId === fanAccountId + type === 1 + accountMediaId; inline bundle — только type === 2 + accountMediaId. Type-less accountMediaId из обычного inline payload не считается покупкой
  • /media/orderhistory вызывается только для unresolved PPV-вложений: single через accountMediaId, bundle через accountMediaBundleId, всегда с accountIds=<fanAccountId> и limit=100
  • Ответ verifier парсится из accountMediaOrderHistory[] и fallback aggregationData.accountMediaOrders[]; строки повторно фильтруются по exact fan/content/kind
  • Verifier ограничен для быстрых replies: cap 10 уникальных PPV-вложений на операцию, concurrency 3, timeout 3s на запрос, in-memory cache 5 минут по (modelAccountId, fanAccountId, kind, contentId)
  • Любая неполная проверка — cap overflow, timeout, malformed response или API error — fail-open'ится в unknown, а не ломает операцию и не превращается в not purchased
  • session-capture теперь знает route key для /api/v1/media/orderhistory, чтобы session/auth check брался из правильного Fansly route
