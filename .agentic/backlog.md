### BL-008 — выжечь длинное тире из ИСХОДНИКОВ промптов (владелец, 2026-07-28)

**Задача (уточнена владельцем):** речь не про пост-обработку вывода, а про сам
текст, который мы отдаём модели. Убрать «—» из коуча, из шаблонов и из ПРИМЕРОВ
внутри них. Модель копирует стиль образца, поэтому дефис в примере дороже дефиса
в инструкции.

**Главная находка — маркеры транскрипта, а не проза шаблонов.** Оба конца
собирают платные вложения строкой `[… — PPV $X.XX, purchased]` через настоящее
длинное тире: расширение `src/shared/transcript.ts:194-198` (`ppvSuffix`, он же
кормит `[Media Bundle: …]`), ядро `prompts/transcript/normalize.ts:67`. Это самый
частый «—» в контексте: он приезжает в КАЖДУЮ генерацию столько раз, сколько в
чате платных вложений, задолго до любой прозы. Грамматику дословно цитируют
`help-me.md:7`, `fast-reply.md`, `improve-draft.md`, `ping.md`, `templates.ts` —
это ровно те «примеры с дефисами». Менять только связкой: два эмиттера + все
цитаты грамматики; иначе цитата разойдётся с живым маркером и модель перестанет
узнавать теги. Тесты, которые упадут и должны быть обновлены: ext
`tests/transcript.test.ts`, `tests/operations-suite.ts`; core
`tests/ai-prompts-templates-sync.test.ts`.

**Остальная проза шаблонов (ядро, `~/code/core`).** Счётчики «—» по
`prompts/templates/`: hi-greeting 23, ping 21, fast-reply 17, help-me 15,
improve-draft 12, chat-review 11, fan-summary 6, fan-summary-short 6,
voice-script 2, coach-chat 1; плюс живые строки в `templates.ts` и `builder.ts`
(tone overrides, заголовок досье, сегменты пингов — комментарии кода не считать).
Отдельно проверено: GOOD/BAD-примеры ответов в `templates.ts:24-80` написаны
короткими дефисами и чисты — там тире только в обрамляющих инструкциях.

**Запрет живёт не там, где нужен.** Явное правило «Never use long dashes» ровно
одно и лежит ВНУТРИ бандла личности Лоры (`prompts/personalities.ts:38`), то
есть не действует ни на коуч-чат, ни на саммари, ни на войс-скрипт, ни на чужие
персоны. Правило нужно в общем output-контракте (feature-policies + шаблон
каждой фичи).

**Осторожно:** у промптов шапка «tuned production assets — do not reword outside
the parity harness»; правка едет вместе с `prompt-manifest.json` и
`tests/ai-prompts-*.test.ts`.

**Хвост (не приоритет, страховка на вывод).** `src/shared/reply-output.ts` —
живой санитайзер вставляемых ответов (`operations.ts`, `content/index.ts`,
`compare-operations.ts`) — тире не трогает. Готовый `normalizeDashes` написан в
ядре (`prompts/output/reply-output.ts:70`: «5–10» → «5-10», прочее тире →
запятая, переносы целы), но та копия в ядре ничем не вызывается — портированный
артефакт десктопа, санитайз живёт на клиенте. При желании перенести в
`sanitizeReplyPart`. Коуч-текст мимо этого пути в любом случае (идёт через
`coach-format`/`coach-draft`) — ещё одна причина чинить исходники, а не вывод.
Десктоп (`~/code/chatgoose_desktop_fable`) проверить на тот же разрыв.

### Core deploy — безопасное применение migration 0106

До первого применения Core migration `0106_ai_generation_content_fan_ref.sql` в
окружении проверить `schema_migrations` и `pg_index.indisvalid`. Если `0106` ещё
не применена, заранее выполнить metadata-only column add и неблокирующую сборку
индекса отдельными autocommit-командами (не внутри transaction block):

```sql
ALTER TABLE ai_generation_content ADD COLUMN IF NOT EXISTS fan_ref text;
CREATE INDEX CONCURRENTLY IF NOT EXISTS ai_generation_content_page_fan_idx
  ON ai_generation_content (page_id, fan_ref) WHERE fan_ref IS NOT NULL;
```

Затем запускать обычный migration runner: его plain `CREATE INDEX IF NOT EXISTS`
станет быстрым no-op. Уже опубликованную forward-only migration не переписывать;
новая migration после 0106 не может устранить блокировку внутри самой 0106.
