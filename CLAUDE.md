# CLAUDE.md — ChatGoose (Fansly extension)

Firefox MV3 extension (gecko ≥ 142) for agency chatters working Fansly.com:
injects an AI assistant into the live Fansly DOM (replies, coaching, fan
summaries, pings, spenders board, vault uploads, followers). It is a client
of the Agency Hub (`~/code/1-platform/hub`, "the kernel"): the hub holds the AI
keys, assembles prompts and computes money; this repo reads the Fansly page
and talks to the hub through the vendored SDK. Product description, features
and current architecture: `README.md` (kept current). Sibling for OnlyFans:
`~/code/1-platform/onlyfans-chat`.

## Layout and checks

Plain TS + esbuild (`esbuild.config.mjs`), no framework in content scripts.
`src/{background,content,options,popup,shared,debug-followers,debug-prompt}`,
tests in `tests/` (vitest), vendored hub SDK in `vendor/kernel-sdk`.

- `pnpm check` = typecheck + lint + gates + test + build; CI runs it on PRs
  and pushes to main, on the PC runners as the same parts through
  `scripts/ci-parallel-check.mjs` (typecheck, lint and gates side by side,
  then test, then build; a new part runs alone until the script lists it
  as read-only, and the script pins each read-only part's exact body: any
  other body runs plain `pnpm check`). `pnpm gates`
  (`scripts/check-ai-cutover.mjs`) greps the kernel-only-AI invariants; only
  grep's "no match" exit passes, a missing file or a grep error fails it.
- `vendor/kernel-sdk` is generated by the hub's `scripts/vendor-sdk.mjs`;
  never hand-edit it. The vendor test and typecheck pin the contract hash.
- `vendor/chatgoose-hotkeys` (`@chatgoose/hotkeys`) is generated by the hub's
  `scripts/vendor-hotkeys.mjs`; never hand-edit it. It is the hotkey scheme
  shared with the desktop app — the spec is the hub's
  `packages/chatgoose-hotkeys/README.md`; both clients ship the same manifest
  sha256. `src/shared/hotkeys.ts` only adapts it (E141).

## Things that bite

- AI is kernel-only: no vendor SDKs, keys or prompt assembly here.
  Generations send refs + `clientContext` to `/api/v1/ai/features/<feature>`
  and stream SSE; a truncated stream is an error, never a result.
- Sign-in is login + password → hub device token
  (`src/background/device-token.ts`); the legacy chatter key is gone (E123).
- The extension is the LIVE reader of Fansly; the hub's archive is
  pull-cadenced. Don't replace a live read with a hub read.
- Fansly egress rides the chatter's own session. Extra requests to Fansly
  exist only where the hub can't do the job (vault uploads, follower reads)
  and carry pacing + cooldown (E109–E122); anything new without pacing
  risks a model ban.
- AI never sends without explicit human action; never auto-retry an
  indeterminate send.
- Storage: numbered forward-only migrations in `src/shared/migrations.ts`;
  `STORAGE_SCHEMA_VERSION` in `src/shared/constants.ts` is the source.
  Hub credentials live in their own storage keys; every full-state persist
  goes through `serializePersistedState`.
- Money: the hub returns integer mills; conversion, tiers and formatting
  live in `src/shared/spenders.ts`, don't add parallel math.
- Release: bump `package.json` + `manifest.json` together, update
  `CHANGELOG.md` + `changelog.html`, run `scripts/deploy.sh` (signs, checks
  served == manifest == package.json, uploads). Pages only:
  `scripts/deploy.sh --pages-only`. The self-hosted feed is the only
  distribution channel.
