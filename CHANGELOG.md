## 1.9.0

Панель действий пересобрана — тоны стали переключателями с эмодзи, Split не слетает при регенерации; доска Spenders видит всех китов ядра, месячный приток и поиск.

### ⚠️ Изменилось поведение

- **Тоны больше не стреляют сразу.** Клик по тону теперь только армирует его для следующего Reply (повторный клик — снимает); запускает генерацию только кнопка Reply. Тонированный ответ — два клика: тон → Reply. Зато тоны и Split ведут себя одинаково — как опции одного действия.

### ✨ Изменено — панель действий

- **Тоны — эмодзи-переключатели в жёлобе у Reply.** 😌 Casual · 😏 Flirt · 💰 Sell · 🔥 Spice — тон выбирается один (радио), армированный подсвечивается и подписывается словом. Наведение показывает описание тона по-русски. Casual вернулся на панель (и в цикл ⌘⇧O).
- **Split вместо Multi — и он больше не слетает.** Переключатель с квадратной точкой: включён — ответы идут серией, пока не выключишь сам. Раньше режим молча сбрасывался после каждой генерации, из-за чего Regenerate терял разбивку. Regenerate теперь повторяет исходный запрос полностью — и режим, и тон.
- **Сплит надёжнее.** Расширение распознаёт маркер разбивки в любом написании (`[next]`, `[ NEXT ]` — раньше такие склеивались в одно сообщение), а ядро после ближайшего обновления хаба будет обязано вернуть 2–3 сообщения при включённом Split — «попросил серию, получил одно» уходит.
- **Переименования.** Polish → **Fix**, Scan → **Recap**, Multi → **Split** — теперь панель, оверлей и шпаргалка `?` называют фичи одинаково.
- **Панель сгруппирована по смыслу.** Reply со своими опциями │ Fix │ Hi · Ping │ справа — Recap (с точкой готовности) и персона.

### ✨ Изменено — доска Spenders

- **Видны все спендеры ядра.** Раньше кит, не писавший последние 150 чатов, молча выпадал из рейтинга. Теперь в списке все (до 500); у фанов без недавнего чата — пометка «no recent chat», при открытии расширение само находит чат через поиск инбокса.
- **Месячный приток и бейдж NEW.** Зелёное «+$N» под лайфтаймом — сколько фан принёс в этом календарном месяце; NEW — у тех, чья первая трата случилась в этом месяце. Если месячных данных у ядра нет, колонка честно не показывается.
- **Поиск по доске.** `/` фокусирует поле, ввод фильтрует по имени и хендлу; j/k при этом не трогают курсор.
- **Честная свежесть.** Шапка различает «data as of …» (свежесть данных ядра) и «fetched …» (когда список получен); подсказка объясняет: хаб перечитывает Fansly по своему расписанию, Refresh лишь забирает последний снапшот.
- **Чат открывается без перезагрузки страницы.** Enter/клик по строке переключает роут внутри Fansly; если роутер не отреагировал — обычная полная загрузка, как раньше.
- **Доска не пересобирается после простоя.** Кэш (10 минут) переживает рестарт фонового процесса.

### 🔧 Технически

- Spenders: `fanCount` = полный счёт ядра («top N of M spenders»); новый runtime-запрос `resolveFanChat` — один поиск `/messaging/groups?search=` (тот же эндпоинт и параметр, что родная строка поиска инбокса, нового egress-класса нет); лимит kernel-запроса 500; кэш write-through в storage.session, not-ramped не кэшируется.
- Бар: тоны — radiogroup с aria-checked; реген-память тона очищается при смене чата; `splitByNext` толерантен к регистру/пробелам маркера (скобочные формы; голое «NEXT» в тексте не режет).
- Kernel-половина сплита — ветка core `ai/split-mode-always-splits` (промпт: всегда ≥2 части, ≤3); вступает в силу с деплоем хаба, порядок деплоя свободный.

## 1.8.1

Кастомные личности наконец работают с ядром, борд честно говорит «рейтинги не включены», токен устройства больше не теряется, и очень длинные чаты не роняют генерацию.

### 🐛 Исправлено

- **Кастомные личности заработали.** Раньше добавленная в настройках личность существовала только локально — ядро её не знало, и генерация на аккаунте с такой личностью падала с невнятной ошибкой. Теперь каждая личность синхронизируется с ядром: сохранение — обновляет, удаление — архивирует, а при старте расширение досинхронизирует всё, что было создано раньше.
- **Токен устройства больше не теряется.** Открытая вкладка настроек могла молча затереть свежевыданный токен устройства своим отложенным сохранением. Токен и ключ переехали в отдельные ячейки хранилища (схема v13) — настройки их больше не трогают.
- **Свежий Fan Summary снова кэшируется.** Из-за устаревшей проверки модели результат генерации не попадал в кэш — каждый повторный запрос генерировал заново. Починено.
- **Очень длинные чаты не роняют генерацию.** Транскрипт обрезается на стороне расширения до лимита ядра (300 тыс. символов), отбрасывая самые старые сообщения — раньше такой чат получал отказ целиком.

### ✨ Изменено

- **Борд честен про пустоту.** Если рейтинги трат для страницы ещё не включены на стороне ядра, борд говорит именно это — вместо ложного «No paying fans… updated just now». Состояние не кэшируется: борд оживёт сразу, как рейтинги включат.
- **Встроенная личность Lora — только для чтения.** Локальные правки встроенной личности всё равно молча игнорировались при генерации (ядро собирает промпт из своей копии) — теперь карточка честно закрыта от правок. Кастомные личности редактируются как раньше и синхронизируются.

### 🔧 Технически

- Настройки: схема v13 — hub-креды в отдельных ключах storage.local (атомарная запись, RMW-гонка настроек убита).
- Персоны: ключ = локальный id личности (то же значение, что personaKey в генерации); displayName ≤120, systemBlock ≤50k — зеркала схемы ядра.
- Спул acceptance-событий: счётчик потерь пополняется и на 400, и на исчерпании попыток; предупреждения видны в консоли фона; один flush при старте.
- Релизная гигиена: deploy.sh проверяет ветку/чистоту дерева/запушенность/semver фида ДО подписи и ставит аннотированный тег после зелёного деплоя.

## 1.6.0 — Переезд на ядро агентства

**Веха.** ChatGoose перестал быть одиноким расширением со своими ключами и промптами в кармане — теперь это клиент **ядра агентства (Agency Hub)**: общего сервера, где живёт весь интеллект — промпты, персоналии, модели, лимиты и деньги. На той же платформе работает десктопный ChatGoose для OnlyFans. Два клиента — один мозг.

### 🏛 Что это дало

- **Ключи вендоров ушли с машин чаттеров.** Расширение не знает ни одного ключа Anthropic/OpenRouter — разрешения на их домены удалены из манифеста, так что прямой вызов невозможен физически, а не по договорённости. Поля ключей исчезли из настроек, сохранённые значения стёрты при обновлении.
- **Генерация — через ядро.** Reply/Polish/Hi/Ping/Scan отправляют на сервер только контекст беседы; промпт собирает ядро и стримит ответ обратно. Улучшение промптов теперь доезжает до всей команды мгновенно — без релиза расширения.
- **Личный вход вместо общего ключа.** Логин/пароль в настройках → собственный токен устройства: доступ выдаётся и отзывается по-устройственно. Общий API-ключ хаба остался запасным входом ещё на релиз.
- **Борд топ-спендеров стал мгновенным.** Рейтинг — один запрос к готовой проекции ядра с честной отметкой «данные на …» вместо пересборки из ~150 запросов к Fansly при каждом открытии. Квота Fansly почти не тратится.
- **Персоналии живут в ядре** — их видят и расширение, и десктоп; привязки аккаунтов остаются локальными.
- **Лимиты и учёт — на ядре.** Квоты генераций и стоимость считает сервер; клиенту нечего подделывать и не с чем расходиться.

### 🔧 Технически

- Разрешения на `api.anthropic.com` и `openrouter.ai` удалены из манифеста.
- Выбор модели и «reasoning» на клиенте убраны — моделями управляет ядро.

## 1.2.17

Финальная v2-проверка PPV в ChatGoose. Главный баг прошлой версии был в том, что расширение смотрело на «куплено» с точки зрения модели/viewer-side флагов Fansly. Для модели свой PPV-контент часто выглядит доступным, поэтому AI мог решить, что фан уже купил видео или бандл, и отвечать так, будто контент разблокирован.

Теперь ChatGoose проверяет покупку с точки зрения конкретного фана. Это снижает риск неправильных PPV-ответов и ложных предположений о покупке: AI больше не должен поздравлять с просмотром, повторно питчить уже купленное или уверенно говорить «не купил» без проверки. Это не обещание идеального совпадения со всеми внутренними состояниями Fansly — если доказательств не хватает, статус остаётся `unknown`.

### Главное

- `purchased` ставится только когда найден точный заказ этого фана на этот конкретный PPV-контент.
- `not purchased` ставится только после успешной точной проверки `/media/orderhistory`, если заказ для пары «фан + контент» не найден.
- `unknown` ставится, когда не удалось определить фана, нет нужных API-данных, проверка заказа не сработала, упала, истекла по таймауту или часть вложений не попала в лимит проверок.
- Чаевые и embed-only сообщения (GIF/превью ссылок) больше не превращаются в ложные `[Media]`.

### Подробности

- **Fan-perspective вместо viewer-side**: `media.purchased` и похожие model-side флаги больше не считаются доказательством покупки фаном. Inline-заказы из `/message` учитываются только после фильтрации по `fanAccountId` и точному `accountMediaId` / `accountMediaBundleId`.
- **Точная проверка `/media/orderhistory`**: для PPV-вложений, которые не удалось подтвердить из inline-данных, ChatGoose делает отдельный запрос по конкретному `accountMediaId` или `accountMediaBundleId` и `accountIds=<fanAccountId>`. Пустой успешный ответ даёт `not purchased`; ошибка, malformed response или таймаут оставляют `unknown`.
- **Статусы без догадок**: `purchased` означает «найден exact fan+content order»; `not purchased` означает «exact verifier check succeeded and found no order»; `unknown` означает «нет надёжного доказательства в обе стороны».
- **Меньше ложных media-меток**: `contentType: 7` (tip) больше не падает в `[Media]`, а embed-only сообщения вроде Tenor GIF или preview-картинок ссылок не маркируются как медиа-вложения.
- **Лучшие labels для медиа и бандлов**: тип медиа берётся из вложенного `media.media.{type,mimetype}` с fallback на top-level поля; состав бандла считается через `bundleContent[]` и `accountMediaIds[]`. Формат стал человеческим и с правильным singular/plural: `1 Photo`, `2 Videos`, `[Media Bundle: 1 Photo, 2 Videos — PPV $X.XX, unknown]`.
- **Промпты стали осторожнее**: `fast-reply`, `improve-draft`, `help-me` и `ping` явно объясняют AI, что PPV-цены и bracket-теги нельзя цитировать фану, а при `unknown` нельзя утверждать ни что фан купил контент, ни что он его не купил.

### Технически

- `normalizeTranscript()` теперь принимает `PurchaseEvidenceOverride`: inline `/message.accountMediaOrders[]` даёт только positive proof, а `checkedNotPurchased*` приходит только из exact verifier.
- Inline single засчитывается только как `accountId === fanAccountId + type === 1 + accountMediaId`; inline bundle — только `type === 2 + accountMediaId`. Type-less `accountMediaId` из обычного inline payload не считается покупкой.
- `/media/orderhistory` вызывается только для unresolved PPV-вложений: single через `accountMediaId`, bundle через `accountMediaBundleId`, всегда с `accountIds=<fanAccountId>` и `limit=100`.
- Ответ verifier парсится из `accountMediaOrderHistory[]` и defensive fallback `aggregationData.accountMediaOrders[]`; строки всё равно повторно фильтруются по exact fan/content/kind.
- Verifier ограничен, чтобы не убить быстрые replies: cap 10 уникальных PPV-вложений на операцию, concurrency 3, timeout 3s на запрос, in-memory cache 5 минут по `(modelAccountId, fanAccountId, kind, contentId)`.
- Любая неполная проверка (`cap overflow`, timeout, malformed response, API error) fail-open'ится в `unknown`, а не ломает операцию и не превращается в `not purchased`.
- `session-capture` теперь знает route key для `/api/v1/media/orderhistory`, чтобы session/auth check брался из правильного Fansly route.

- `fast-reply`: добавлен блок Anti-AI Rules — забанена структура "validate → elaborate → question", список запрещённых фраз ("hits different", "I don't take that lightly", "that's actually meaningful" и др.), ограничение длины по умолчанию, правила для эмоциональных моментов, self-test
- `improve-draft`: добавлен Anti-AI блок — запрет раздувать простые мысли, бан AI-фраз, контроль длины
- `help-me`: suggestions теперь проходят anti-AI фильтр — без терапевт-энергии и мотивационных шаблонов
- `hi-greeting`: запрет generic enthusiasm и AI-polish в вариантах приветствий
- `ping`: бан на "you crossed my mind", "just been thinking about you" и прочий AI-slop
- Основано на анализе реальных чатов + Wikipedia "Signs of AI writing" (29 паттернов)
